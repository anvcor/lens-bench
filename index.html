镜头数据管理器

—

逐颗翻看：光标不在输入框里时，键盘 ↓ / ↑ 切到下一颗 / 上一颗镜头，翻到一个品牌的头尾会接着进入下一个 / 上一个品牌，像看幻灯片一样一路看下去；按住不放时下拉跟着走，松手才载入那一颗。

编辑：直接改单元格；点「表面编号」格可把该面设为光阑。手机上面数据表格、镜头信息卡、波长设置都默认收起（选完镜头往下一屏左右就是 Layout 和 MTF），点各自的「展开…」再看 / 改。

镜头信息卡（表格下面那块）：上半是标称——专利号（点开是 Google Patents 检索）、型号代码、卡口 / 画幅 / 类型、标称焦距与光圈、发售年份，来自《镜头仿真进度表》，由 tools/specs_import.py 写进 lenses/meta.json；表里没有的镜头（唯卓仕、七工匠等）只有下半。下半是本页按当前状态算出来的：焦距、F/#、总长、后截距、入瞳、最大像高、片数，以及大致性能——轴上 / 边缘 RMS、前两个频率的中心 / 边缘 MTF、边缘通光率、最大畸变。改表格、切结构、改物距都会跟着刷新；标称值不变，两边对不上就是数据本身和产品的差别。信息卡下面那个琥珀色提示框只在有需要处理的事时出现（导入文件的解析警告、找不到的玻璃、最佳对焦 / 一键渐晕的结果、渐晕表与瞄准设置不一致、衍射采样不足等）；每颗镜头的数据来源与录入说明放在表头「专利 / 逆向」徽标的悬停提示里。

物面与最佳对焦：物面那一行的厚度就是物距，和顶栏「物距」是同一个量，改哪边都行，写 inf 为无限远；有多重结构时会写回当前结构。改完按最佳对焦：镜头有多个对焦结构时，按镜头自己的对焦群重新对焦——同一焦段、不同物距的几个结构相差的那几个间隔就是对焦群（浮动对焦的几组也一起认出来），把它们按 1/物距 插值成一条对焦凸轮，沿凸轮找轴上 RMS 最小的位置写回表里，像面不动，总长守恒。变焦镜头按当前所在的焦段对焦：先从表里的变焦间隔反推出焦段，再用相邻两个焦段各自的对焦凸轮插出这个焦段的对焦凸轮——正好在文件焦段上时就是那个焦段自己的凸轮，变焦到中间焦段以后也对得上。认不出对焦群（单结构、同物距几组不同间隔、对焦时曲率也在变、插删过面）时退回老办法：移动像面，写进「离焦」。物距超出文件给的对焦行程会提示是外推。

变焦（只在变焦镜头上出现，结构下拉旁边的「焦距 mm」）：填焦距按「变焦」或回车。多重结构里物距无限远、间隔却各不相同的几个结构就是文件给出的几个焦段；各变焦间隔对 1/f 做自然三次样条插值得到变焦凸轮，焦距按对到无限远时的 EFL 精确反解（镜身刻度的意思——对焦群一动 EFL 就跟着变，只看插值结果能差 0.4 mm），再沿插值出来的对焦群按「最佳对焦」同一判据对到当前物距，像面不动；对近处时状态栏的 EFL 会比填的小一点，那是对焦呼吸。各焦段 F/# 不同的跟着插值；渐晕用的是「按通光」的表就在新焦段上按真实通光重算，用文件系数的就在两侧焦段之间插值。中间焦段是估计：文件只给了几个焦段，节点之间真正的凸轮不知道。拿 FE 12-24 GM 的 5 个焦段做留一法（拿掉一个、用其余的预测它，对焦后比画质），1/f 自然样条的 0.7 视场 RMS 平均是真值的 1.6 倍、最差 2.2 倍，按焦距直线插值是 5~11 倍；实际用时节点间距只有留一法的一半，误差更小，但离轴画质仍只供参考；文件焦段稀、相距远时误差会大得多——尼康 Z 24-70 II 只给了 24.7 / 50 / 67.9 三个焦段，插到 30 mm 边缘 RMS 57 µm，两端焦段只有 14 / 20 µm，多半是凸轮猜偏了，提示里会单独警告。填的焦距离文件焦段不到 0.05% 就直接用那个焦段的原始数据。

变焦凸轮数据：镜头带凸轮数据时（ZoomCam_Test 导出的 <tag>_凸轮数据.json，镜头库里由 tools/camattach.js 挂上；也可以在当前镜头上按「导入」选这个 .json 现场挂，先和镜头的 ∞ 结构逐个对账，差超过 20 µm 不挂），变焦和对焦都按它走，不再从多重结构里猜：变焦取 ∞ 节点（CODE V 逐点评价过的凸轮，一般 161 个，间距 0.5°）在 x = −1/f 上的样条值，参数修到本页 EFL 正好等于填的焦距；∞ 位置直接用节点、不再按轴上 RMS 重新对焦（凸轮是按 MTF 判据求的）。对焦按对焦表：对焦间隔 = 节点的 ∞ 位置 + 表里的增量，行内按 1/D 线性（D = 物面到像面，本页「物距」加上第 1 面到像面），焦段之间按 ln f 线性；比表里最近的物距还近会外推并提示，比该焦段的最近对焦距离还近就夹到最近对焦距离。F/# 按表里的工作 F/#（光阑物理大小固定）等比例跟着变。「最佳对焦」这时就是查对焦表：先按表格里的变焦间隔认出在凸轮的哪一点，再对到当前物距。信息卡上会多一段「变焦凸轮」，写着数据来源、节点数和当前在凸轮上的焦距与转角。

半孔径：格子里有数（CODE V 的 CIR 或手填）是硬光阑，追迹时光线超出即被挡。没数的面用灰字显示参考值，不挡光，鼠标停上去看来源：文件里写死的通光（Zemax 固定 DIAM / FLAP，「一键渐晕」和 Spot 按它逐面裁剪）→ 文件的半口径（Zemax 自动 DIAM，只用于画图）→ 本页按光线包络算的画图半径。在灰字格里填数就变成硬光阑。

多重结构：.seq 里的 ZOO 记录（结构数、各结构标题、逐结构的 FNO / 面厚度 / 曲率 / 渐晕系数）会读进来，用工具栏「结构」下拉切换，随结构变化的格子在表里标了色，改这些格子会写回当前结构。物面厚度（ZOO THI S0）落到顶栏「物距」，因此近摄结构按有限共轭追迹：光线从物点发出而非平行入射，F/# 用像方工作 F/#（由近轴边缘光线角 1/(2|u′|) 反解入瞳），状态栏 RED 给出放大倍率。

光线瞄准默认开着：归一化瞳坐标只有定义在光阑面上才有意义。关掉的话它落在近轴入瞳上，视场一大瞳像差就把这个参数化整个扭掉——FE 14mm F1.8 GM 的 56.7° 视场上，u = −1…+1 只覆盖光阑的 +0.13…+0.84，主光线（u=0）落在 0.47 处，整束光线跑到光阑上半边，下缘瞳位置和边角 MTF 全错；FE 35mm F1.4 GM 的 32.4° 则是 u = −1 落到光阑外 1.20 倍处。规规矩矩的镜头开不开几乎没差（85 GM II / 55ZA / CODE V 对照实测 MTF 差 ≤ 0.005），代价是追迹慢一些。

渐晕：若文件带 SETVIG / VDYN·VCYN 存的 VUY/VLY/VUX/VLX，瞳区间直接按它逐视场插值取，不再靠通光孔径反推——很多 .seq 只在像面写 CIR，镜片没有孔径数据，这时这张表是唯一依据。

一键渐晕：文件存的系数常常和它自己的通光对不上（Zemax 的浮动通光逐结构重算，系数却只存了一份），画出来就是光线穿出镜片。按 CODE V 的 SET VIGNETTING 重算当前结构的渐晕系数——把 ±Y / ±X 四条边缘光线二分推到「刚好通过全部真实通光」为止，21 个视场点，能收紧也能放开。判据只认写死的通光（CODE V 的 CIR、Zemax 的固定 DIAM 与浮动通光 FLAP）；自动算出来的 DIAM 是光线包络反推的，不是物理孔径，不参与；光阑面也不参与——归一化瞳坐标 ±1 定义的就是它的边缘，它不会渐晕自己。弧矢跨度在子午瞳的中心那一行量，不是在 y = 0 上量：渐晕后的瞳是偏心的（FE 85mm F1.4 GM II 最大视场瞳心在 −0.32），在 y = 0 上量等于量到瞳边缘的一条弦，弧矢瞳会小掉一大截（0.52 而不是 0.86），MTF 反而虚高。Zemax 的 VDX/VCX 也是这个意思——X 边缘光线走的是 Py′ = VDY 那一行。库里的镜头已经逐结构预先跑过一遍（tools/setvig.js），载入即生效，按钮显示为「渐晕：按通光」；再按一下即换回文件自带的系数，可以直接看出偏了多少，Ctrl+Z 也能来回。没有渐晕系数的镜头（瞳本来就按通光实时追迹）不预算；另外几种情况也有意跳过并在提示里说明原因：写死通光的面数达不到下限（至少 4 个面、且至少占总面数的 20%；拿 3 个面去解 21 个视场的渐晕剖面，解出来的瞳只是这 3 个面的形状，和真实镜筒无关）、真实通光太少（定不出渐晕剖面）、通光够多但全程只有一个面在限制光瞳（真正卡光的面没写进文件，放开只会把瞳算得比实际大），以及写死的通光其实挡不住任何光线——按文件自带的渐晕系数追一遍包络，如果每个通光都 ≥ 自己的包络，说明它们只是被 Zemax 的 Set Semi-Diameters 冻结下来的自动半口径，不含新信息（FE 16mm F1.8 G 的 S16 写死 8.80，而文件渐晕追出来的包络正好是 8.8025）。这几种都保留文件自带的系数，按钮仍可手动按。拿带 SETVIG 的 CODE V 文件反过来校验，本页重算的系数与文件自带的差 ≤ 0.03（归一化瞳坐标，满瞳半宽 = 1）。

撤销：所有改动（含「最佳对焦」写入的对焦群间隔或离焦量、改物距、插删面、波长预设、粘贴）都可 撤销 / 重做，快捷键 Ctrl+Z / Ctrl+Shift+Z（光标停在输入框里时让给浏览器的文本撤销）；恢复初始回到刚载入示例或刚导入 .seq 时的状态，这一步本身也能撤销。

粘贴：从 Excel / 专利表格复制多行多列，选中起始格 Ctrl+V 即整块填入（列顺序 Radius→厚度→玻璃→半孔径→圆锥→A4 A6 A8…），行数不够会自动补。

非球面：A4 A6 A8… 每项一列，列不够时最右会自动多出一列；表格可左右滚动。扩展奇次非球面（Zemax 的 XOSPHERE，富士等专利里印成 A3…A20 那种带奇数次的级数）表面类型列显示「扩展奇次」，系数格依次是 Rn A1 A2 … AN：z = 圆锥 + Σ Aj·(r/Rn)j，数字就是文件 / 专利印的原值，不做换算；要手工把一面改成这种，在它第一个系数格写 XODD，格子会右移成 Rn A1 …；清空全部系数换回球面。同一颗镜头里偶次和扩展奇次混用时，表头上下两行分别标两种的项名。早先的写法（第一格写 ODD，后面是已除掉 Rn 的 r¹ r² r³ … 实际系数）照旧认。

材料：直接写牌号，内置 — 种厂商目录玻璃（SCHOTT / OHARA / HOYA / HIKARI / CDGM / SUMITA / NHG / CHINA / SPECIAL 等 19 家），输入时会自动补全；重名可用 牌号_目录 指定（H-ZF72A_CDGM、NBFD25_HOYA、SBSL7_OHARA）。查不到的写 nd/vd（如 1.7292/54.7）或 6 位 MIL 代码（如 517640）按模型玻璃算；写 nd/vd/ΔPg,F 三段可指定反常色散。玻璃偏移解写成 牌号~Δnd~Δνd（如 S-NBH52V~-0.00735~-2.6561）：照搬基准玻璃的色散曲线形状、只把 nd 和 νd 挪到偏移后的值，相对部分色散不变，对应 Zemax 的 GLAS … 4 … Δnd Δνd，专利仿真里用来还原没有等效牌号的元件。留空为空气。CODE V 的数字式虚拟玻璃 nnnnnn.vvvvvv（如 560412.639175 → nd 1.560412 / νd 63.9175，整数部分 =(nd−1)×10⁶、小数部分 = νd/100）也认，常见于複合型非球面的树脂层；认不出来整个面会被当成空气，所以宁可解错也要解。但这只是兜底，解出的 νd 已知不可信——同一片树脂，原始文件写的是 1.56093 / 36.6，CODE V 重导出后按上式解出来是 63.9175。每遇到一个都会把面号和解出的值列进导入提示；出现这种写法基本说明该文件是 CODE V 往返导出的产物，建议回去用原始文件。

导出：「导出 .zmx」「导出 .seq」把当前镜头连同全部多重结构存成 Zemax / CODE V 文件，写的就是本页此刻在算的东西——表里改过的数据（当前结构直接取表格，其它结构取各自存的厚度 / 半径 / 物距 / F/#）、离焦、视场（库里镜头用原文件那几个）、各结构的渐晕系数、真实通光、偏移解玻璃、偶次 / 扩展 / 奇次非球面和衍射面。.zmx 的孔径照本页的定义写（像方 F/#、工作 F/#、入瞳直径、光阑浮动）；.seq 一律写入瞳直径（CODE V 的 FNO 在近摄时是工作 F 数，和像方 F/# 不是一个量），CODE V 没有偏移解，那几片写成数字式模型玻璃，CODE V 自带目录里没有的少数新牌号（S-LAH66N、S-LAL18N 等）也写成模型玻璃，玻璃对照写在文件头注释里。导出的文件能用「导入」原样读回来；在 OpticStudio 24.2 和 CODE V 2026 里打开，各结构焦距 / 入瞳 / 总长和原文件一致。

导入：CODE V .seq 读面数据 / CIR 通光 / ASP 非球面（到 J = r²⁰）/ SPS ODD 奇次非球面 / DIF DOE 衍射面 / STO / FNO·EPD / WL·WTW·REF / YRI·YAN / SETVIG 渐晕 / ZOO 多重结构 / 数字式虚拟玻璃（xxxxxx.yyyy 和 nd:νd 两种写法）；Zemax .zmx（UTF-16 或 UTF-8）读 SURF·CURV·DISZ·GLAS·CONI·PARM / STOP / FNUM·ENPD / FTYP·YFLN / WAVM·PWAV / VDYN·VCYN 渐晕 / MNUM·THIC·APER·FVCY 多重结构。两种格式走的是同一份解析代码，命令行批量转换用的也是它。

# 波长 nm 权重 占比 绘图颜色 主

预设：可见光 5 线（10/27/29/23/11）、VIS Weighted（C–g 五线按 5500 K 黑体加权，权重 0.898/0.973/1.000/0.984/0.911）、Leica Weighted（短端截到 455 nm、长端用 C′ 线 643.8 nm，权重 7/8/9/7/4）、日本厂商光谱权重（3/22/30/12/3，重心压在 e 线）。主波长一律取 546.1 nm（e 线绿光）——「F d C 等权」和「d 单色」里没有这条线，只能退回 d 线 587.6。绘图颜色按波长的真实谱色算：CIE 1931 配色函数（Wyman/Sloan/Shirley 多高斯拟合）→ sRGB，出色域直接截负、色相饱和度不动、亮度归一到同一目标，所以深浅两个主题下都看得清。改波长会自动重算颜色。

权重按通量参与多色 MTF 合成——各波长的复数 OTF 加权求和后取模，参考点是多色质心，因此色焦移会如实压低 MTF。主波长用于近轴量、光线瞄准、衍射极限参考线和单色 Layout。颜色可点开手动改，改到波长上就会被重算回谱色。Layout 切到「按波长着色」时使用（同时用线型区分，不只靠颜色）。

按「生成 Spot」开始：镜头与像面不动，只把物点移到对焦距离和焦后 / 焦前两个物距上，出各视场的光斑。一次几十万条光线，不跟着编辑自动重算。

算的是什么：几何点列图。镜头结构、光圈、像面位置都按当前状态不动，物点放在三个物距上——对焦物距（当前「物距」，无限远也可以），以及自动搜出来的焦后（更远）和焦前（更近）两个物距：搜索条件是轴上离焦光斑外径 = 目标光斑（默认 600 µm），在 1/物距 上两轮网格 + 插值。无限远对焦只有焦前。每一行共用同一组物方视场角（按当前视场定义等分，视场角在对焦物距上换算）。

光斑形状从哪来：瞳面在光阑上分层随机采样，每条光线瞄准光阑；谁把光线挡掉决定了形状。镜头有足够多写死的真实通光（CIR / 固定 DIAM / FLAP，门槛和「一键渐晕」一样：≥4 个面且 ≥20%）就逐面裁剪，猫眼是真的；不够就退回渐晕系数给的等效椭圆瞳，光斑只能是椭圆——用的是哪种写在图下面。400 µm 量级的离焦盘上衍射没有意义，不算。

读数：D = 全部波长落点离主光线的最大距离 ×2；rms = 主波长落点对自身质心的 RMS；T = 主波长通过率（瞳面均匀采样里通过的比例）。每一行按该行最大光斑取同一比例尺，所以同一行里格子之间的大小可以直接比。亮度映射：能量占 90% 的阈值映到中灰，再往上柔和压到白，离焦盘的亮环和对焦光斑的核心都看得见。

怎么画的：普通点列图。瞳面分层随机取点，每条光线追到像面点亮一个像素，各波长按颜色叠加，密处到白。颜色按「无渐晕的均匀盘应当是白的」做了白平衡，色边才是真的色差而不是权重偏色。不做衍射。

性能：计算在后台 Worker 中进行，逐格出图。「计算引擎」有两个：JavaScript（双精度）是默认，多线程：按 CPU 逻辑线程数开后台线程（留一个给页面，最多 15 个），每格（物距 × 视场 × 波长）的随机瞳点只跟格子编号有关，所以分给哪个线程都一样，结果和单线程逐位相同。8 核 16 线程的笔记本上，5 万条 × 5 波长 × 6 视场 × 2 行（约 300 万条）从单线程 15.5 s 降到 2.7 s，「30 万」档约 12 s；WebGPU（单精度）同样的设置约 1.5 s，GPU 搜索物距、生成光线、重瞄准、追迹、统计和成图，主光线与瞄准表仍由 CPU 双精度建立，图像先返回、统计标签随后显示。两者读数逐格对过（FE 12-24 GM，12 格的 D / rms / T 全部一致）。选了 WebGPU 才开始编译着色器，下拉项上会显示「编译中」：Windows 的 Intel 核显上约 6 秒，编译期间点「生成」会等它。编译好的 GPU 设备、着色器和光学准备数据在本页内复用，中途切到 JavaScript 算也不会丢；按「停止」后要重新编译。浏览器不支持 WebGPU 时这一项是灰的。格子的显示宽度随卡片调整，「每格渲染像素」决定画布分辨率。修改镜头参数不会自动重算点列图，右上角会标「已过期」。WebGPU 后端由 simon300000 贡献（PR #4、#5、#6）。

A 用冷色、B 用暖色，同一颗镜头里颜色深浅区分频率；实线 = 子午 T，虚线 = 弧矢 S（与主页面同一约定）。 两边共用光谱、频率、算法、瞳面网格和视场点数，视场定义 / 渐晕各自按文件走——这是镜头本身的规格，强行统一反而不是那颗镜头了。 光圈默认也各按文件（通常就是全开）。两颗光圈不同时，选「大光圈收到和另一只一样」会把 F/# 小的那只收到另一只的工作 F/#； 选「两只都收到指定 F/#」则两只各自收到填的值（已经比它暗的保持全开，镜头开不到比设计更大的光圈）。 收光圈就是把光阑缩小，渐晕随之重算：别的镜片挡掉的那部分光线不变，只是再和更小的光阑取交集， 所以新的渐晕系数 = 原渐晕区域按新旧光阑半径之比换算后裁到新光阑以内。这和收完光圈重跑一次「一键渐晕」的结果一致 （镜头库里有通光数据的镜头，全部结构 × 5 档收缩比实测，差别在 0.006 以内；收得很小时换算反而更可靠——重跑会漏掉只剩一条细缝的边缘视场）， 而且对文件自带的系数、按可制造性反解的系数同样成立，不依赖镜片通光写没写全。 收光圈后两边的衍射极限虚线会重合，剩下的差别就只是像差本身。 光谱默认统一到可见光 5 线（10/27/29/23/11，主波长 546.1 nm）：两颗镜头文件自带的谱段常常不一样，不统一就不是同一把尺子；选「各自文件自带」才各按各的。 横轴选「实像高」时两颗按各自的毫米数画，画幅不同的镜头这么比才有意义；选「归一化视场」则各自压到 0~1，比的是相对边缘表现。 各自最佳对焦勾上后，每颗镜头各自解一次轴上最小 RMS 离焦再算 MTF——文件后焦有零头时（比如取整过的空气间隔）用它比才公平。 渐晕默认用镜头库里预先按通光重算过的那份（和主页面一致）；渐晕用文件原值勾上后退回文件自带的系数，可以直接看出文件的渐晕表偏了多少。
